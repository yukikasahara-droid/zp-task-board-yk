# 要件と設計方針（REQUIREMENTS）

2026-10-08 夜、ユーザー（笠原）が「最初の版は形になっただけで全く使いやすくない」と判断し、要件を整理し直したもの。
**これが現時点で最も新しい要件。** `HANDOFF.md` の古い記述（「サイトは閲覧専用」など）と食い違う場合は、こちらを優先する。

## 1. 目的

- 複数人で、お互いのタスクを共有できる
- 納期・担当者・周辺情報を、見やすく、同期しやすく持てる

## 2. タスクの登録方法（3つ）

| # | 入口 | 内容 |
|---|---|---|
| 1 | Slack | メンション先が担当者。本文に納期があれば読み取る（現状どおり） |
| 2 | サイト | 新規登録と**既存タスクの編集**ができる |
| 3 | カメラ | 付箋に書いたタスクを撮影 → 文字を読み取って**タスクの下書き**にする（確認してから保存） |

## 3. 避けたいこと（最優先の設計課題）

1. **優先度がわからない**
   - 納期が近いものは当然高い。ただし**タスク自体の重さ**も考慮する。
   - **タスク同士の前後関係**がある（タスクAをやらないとタスクBができない）。
2. **終わったタスクをすばやく消せない**
   - できるだけ少ないアクション（理想は1タップ）で完了にできる。

## 4. 現状の問題（2026-10-08 スマホ画面より）

- 一番上に「期限切れ 982日」のような古いタスクが並び、今やるべきものが埋もれる（期限が近い順 = 古い期限切れが先頭）
- 完了する手段がサイトに無い（Slack スレッドに「完了」と書いて、次の同期を待つ必要がある）
- 優先度・重さ・前後関係の情報が無い
- 編集できない

## 5. 設計案（たたき台・未決定の点は §6）

### 5.1 データ項目の追加

既存の `id, title, body, assignees[], status, assignedOn, due, completedOn, slackUrl` に次を足す。

| 項目 | 内容 |
|---|---|
| `size` | タスクの重さ。`S`（〜1時間）/ `M`（半日）/ `L`（1日以上）。Slack/カメラ登録時は Claude が推定し、サイトで直せる |
| `blockedBy[]` | 先にやるべきタスクの id。これが未完了なら「待ち」状態 |
| `source` | `slack` / `site` / `camera` |
| `updatedAt` / `updatedBy` | 誰がいつ変えたか（同期・衝突の確認用） |

### 5.2 優先度の出し方（自動計算、手動で上書き可）

- 「今やる」候補 = 未完了で、`blockedBy` がすべて完了済みのもの
- スコア = **納期の近さ**（期限切れ・今日・明日…が高い）＋ **重さ**（重いものは早めに着手）＋ **後続の数**（自分が終わらないと進めないタスクが多いほど高い）
- 納期がないものは低めだが、放置日数が長いと少しずつ上げる
- 画面は「**今やる**（スコア順）」「**待ち**（◯◯待ちと表示）」「**納期なし・あとで**」に分ける。担当者で絞ると「自分の今日やること」になる

### 5.3 完了操作

- 一覧の各行に**大きなチェック丸**。1タップで完了 → 行が消え、画面下に「元に戻す」を数秒出す（確認ダイアログは出さない）
- 完了にしたとき、Slack の元スレッドにも「完了」と返信する（任意・後で）

### 5.4 画面

- スマホ中心（現場で片手で使う）。上から：担当者切替 → 今やる → 待ち → あとで
- 古い期限切れの大量表示はやめる。90日以上前の期限切れは「要整理」にまとめて、一括で完了/破棄できるようにする
- カメラ：撮影 → 読み取り結果（タイトル・担当者・納期・重さ）を確認・修正 → 保存

### 5.5 仕組み（現在の「暗号化 JSON を Git で配る」方式は限界）

編集・複数人同時利用・カメラ登録には、**共有データベースと、書き込みの認証**が要る。
Git 管理の暗号化ファイルでは、同時編集が衝突し、ブラウザから安全に書き込めない。

- 画面（静的サイト）は今のまま GitHub Pages で配れる
- データはデータベースに置く（Git からは外す。リポジトリが public でも中身が漏れない）
- Slack の取り込みルーティンは、Git ではなくデータベースに書く
- カメラの文字読み取りは、サーバー側で Claude を呼ぶ（API キーをブラウザに置かない）

## 6. 決定事項（2026-10-08 夜、ユーザー回答）

- **データベース: Google Drive（スプレッドシート）を使う。** 専用の DB サービスは使わない。
  写真は保存しない（読み取ったらすぐ破棄）方針。
- **ログイン: 個人ごとに会社の Google アカウント。** 誰が編集したかを `updatedBy` に残す。共有パスワードは廃止する。
- **カメラ登録: Slack に付箋の写真を投稿する。** 定期実行のルーティンが画像を読み取ってタスク化する。
  サイトに撮影機能は付けない（Claude API の契約も不要）。画像は取り込み後に保存しない。
- 既存74件は `ZPタスクボード（データ）` に移行済み。移行後、Git 上の `data/tasks.enc.json` は廃止する。

### 仕組み（確定案）

```
ブラウザ（GitHub Pages の静的サイト）
  ├─ Google ログイン（Google Identity Services, 内部アプリ）
  └─ Sheets API を本人のトークンで直接呼ぶ ──▶ スプレッドシート「ZPタスクボード（データ）」
                                                    ▲
Claude ルーティン（平日 8:55 / 17:55）──Google Sheets コネクタ──┘
  └─ Slack の依頼・スレッド返信・付箋写真を読み取って追記・更新
```

- スプレッドシートの共有設定がそのままアクセス制御になる（共有された人だけが読み書きできる）。
- 設定の手順は `docs/SETUP-GOOGLE.md`。
- 同時編集: 1行単位で上書きする。同じ行を同時に直すと後勝ち（少人数なので許容）。
